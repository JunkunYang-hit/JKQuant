# JKQuant

一个面向实际选股工作的 A 股日频多因子系统。它在收盘后更新市场数据，计算 8 个可解释的量价因子，过滤不可用股票，做横截面百分位排名并输出 Top-K；可选用 DeepSeek 对 Top-20 做结构化二次复核。系统不训练自己的 AI 模型，也不自动交易。

## 已实现

- Tushare 股票列表、日/周/月线、每日估值、涨跌停、财务三表、宏观经济与 510300 ETF 基准，Parquet 本地增量缓存
- SQLite 持仓账户，持久化保存成本、数量、买入日期和备注
- 可直接运行的确定性样例数据源（仅用于验证安装）
- 动量、趋势、风险、流动性四类共 8 个因子
- ST、退市/暂停上市、上市天数、成交额、零成交过滤
- 因子方向统一、类内加权、类别固定权重、Top-K CSV
- 避免未来函数的滚动计算测试；配置权重自动校验
- Top-10 排名线性加权、每 3 个交易日调仓回测，含买卖佣金、印花税和滑点
- 多套排名进入/退出策略的统一回测、可配置止盈和逐笔盈亏统计
- 回测指标、逐日净值、调仓明细以及净值/回撤图
- 因子 IC/RankIC、五分组收益、滚动稳定性和横截面相关性诊断

## 使用 Tushare 实盘数据

在 `config.yaml` 中把 `data.provider` 改为 `tushare`，然后在项目根目录的 `.env` 填写 Token：

```powershell
# .env 文件内容：TUSHARE_TOKEN=你的真实Token
python scripts/run_daily.py
```

程序会自动读取项目根目录的 `.env`。该文件已被 `.gitignore` 排除，不会被 Git 提交。也仍然支持只在当前 PowerShell 会话中设置 `$env:TUSHARE_TOKEN = "你的 token"`。

日常使用推荐直接运行下面这一条，它会依次拉取截至今天的最新数据、生成当日推荐，然后启动 WebUI 并自动打开浏览器：

```powershell
python scripts/run_today.py --top-k 20
```

`--top-k` 可设为 1 到 50；不填写时使用 `config.yaml` 中的 `strategy.top_k`。例如生成 Top-50：

```powershell
python scripts/run_today.py --top-k 50
```

WebUI 里也可以重新选择 K，推荐表每页最多显示 10 只。数据库统一保存每日 Top-50，页面选择的 K 只是截取前 K，因此 Top-10、Top-20 和 Top-50 会复用同一份缓存。

首次使用新版历史统计时，可以预热 2025-09-01 至今的全部交易日：

```powershell
python scripts/warmup_recommendations.py
```

预热只读取已经下载到本地的 Parquet，不会额外消耗 Tushare 请求次数。程序可重复运行，已经存在的日期会跳过，只补缺失日期。

也可以仅更新数据：

```powershell
python scripts/update_data.py
```

每次运行会从缓存最后日期的下一天开始更新。首次下载约两倍 `history_days` 的自然日，以保证滚动窗口有足够交易日。Tushare 接口权限和积分不足时会原样报告接口错误。

### Tushare 频率与断点续传

Tushare 的限制取决于账户积分，并非所有用户都是同一频率。官方当前权限表列出：120 积分为每分钟 50 次且只能访问未复权日线，2000 积分为每分钟 200 次，5000 积分以上为每分钟 500 次。`daily` 单次最多返回 6000 行，官方说明可按交易日循环提取历史数据。参见 [积分与频次权限表](https://tushare.pro/document/2?doc_id=290) 和 [A 股日线接口](https://tushare.pro/document/1?doc_id=27)。

当前项目按 2000 积分账户设置，常规接口按每分钟 180 次、财务接口按每分钟 75 次运行，分别为官方流控留出余量：

```yaml
data:
  access_tier: 2000
  fetch_stock_basic: true
  fetch_enriched_data: true
  requests_per_minute: 180
  financial_requests_per_minute: 75
  max_retries: 5
  retry_backoff_seconds: 5
  request_timeout_seconds: 15
  basic_refresh_days: 7
```

`daily(trade_date=...)` 一次返回该交易日全市场（本项目实测约 5,550 行）；`daily(ts_code=..., start_date=..., end_date=...)` 返回一个或多个标的一段历史。接口单次上限为 6,000 行。全市场历史应按日期循环，而不是循环五千多只股票。参见官方的 [高效获取数据说明](https://tushare.pro/document/1?doc_id=230)。

下载器会在每次 API 调用前限速，临时错误使用指数退避重试；股票列表提供证券简称、上市状态和行业，日线、周线、月线、每日估值指标、每日涨跌停价格、宏观经济及 510300 ETF 分开落盘。每日流程只做增量更新。

财务三表在 2000 积分档只能按单只股票获取历史，不能按报告期一次提取全市场。首次补齐全市场约需 1.7 万次请求，按 75 次/分钟通常需要数小时。使用独立的断点续传命令：

```powershell
python scripts/update_fundamentals.py --start 2018-01-01
```

可先用 `--max-stocks 10` 验证权限和存储。结果按 `fundamentals/<报表>/<股票>.parquet` 保存，重复运行会跳过已有文件；进度显示在 WebUI 的“数据中心”。新增财务和宏观数据不会未经验证直接混入现有评分，后续应先做因子 IC、分层收益和样本外检验。

### 本地存储为什么同时用 Parquet 和 SQLite

- `daily.parquet` 保存数百万行连续行情，适合 pandas 批量读取和滚动因子计算。
- `selection_results.sqlite3` 从 2025-09-01 起为每个交易日统一保存 Top-50，并建立“策略哈希、日期、排名”复合主键及日期索引。即使页面只展示 Top-20，也不需要重新计算。
- 一年约 240 个交易日，Top-50 也只有约 12,000 条记录，相比数百万行日线非常小。首次预热需要计算，之后读取通常低于 0.1 秒。
- 策略权重或过滤配置变化后，策略哈希随之变化，会重新计算而不会误用旧结果。

Tushare 的 MySQL 示例强调历史数据要落地、建立主键和索引，而不是要求个人项目必须部署 MySQL。当前数据规模使用 Parquet + SQLite 更简单；只有在多用户并发、跨机器共享或数据量继续显著增长时才有必要迁移 PostgreSQL/MySQL。参见 [Tushare MySQL 落地示例](https://tushare.pro/document/1?doc_id=231)。

## 配置与因子

所有策略参数都集中在 `config.yaml`。类别权重必须合计为 1；因子 `direction: 1` 表示越大越好，`-1` 表示越小越好。当前因子为 5/20 日收益、收盘价相对 MA20、MA5 相对 MA20、20 日波动率、20 日当前回撤、20 日平均成交额、5/20 日成交额比。

筛选和打分使用选股日收盘后已知的数据。Tushare 停牌股票通常没有当日 daily 行，因此自然不进入当日横截面。当前 `all_a` 已实现；指数成分股和自定义股票池留待下一阶段。

## 历史回测

默认参数位于 `config.yaml` 的 `backtest` 节点。可以直接使用配置日期：

```powershell
python scripts/run_backtest.py
```

也可以覆盖日期：

```powershell
python scripts/run_backtest.py --start 2025-01-01 --end 2025-12-31
```

输出目录为 `backtests/开始日期_结束日期/`：

- `daily.csv`：逐日毛收益、净收益、成本、换手率、净值和回撤
- `rebalances.csv`：每次调仓的信号日、交易日、买卖换手和持仓代码
- `metrics.json`：年化/累计/基准/超额收益、最大回撤、年化波动、胜率及年度收益
- `equity_drawdown.png`：策略与沪深300ETF（510300.SH）基准净值、策略回撤

信号在 T 日收盘后形成，最早于 T+1 开盘交易。调仓日将旧持仓隔夜收益和新持仓开盘至收盘收益分开计算，避免用 T+1 的价格选择 T 日股票。非调仓日使用收盘到收盘收益。基准使用沪深300ETF `510300.SH` 的同期每日收益；它是独立市场参照，不是用户策略。

当前回测测试的是固定规则：用动量 40%、趋势 25%、低风险 20%、流动性 15% 合成得分，持有前 10 只股票，只做多，并按排名线性分配权重。第 1 名权重为 `10/55=18.18%`，此后依次下降，第 10 名为 `1/55=1.82%`；每 3 个交易日调仓。回测中的“收益”是按这些历史持仓的真实历史价格变化模拟出的组合盈亏；净收益还会扣除佣金、印花税和滑点。它回答的是“过去机械执行这套规则会怎样”，不代表未来能获得相同收益。

### 多策略回测

执行统一的策略横向比较：

```powershell
python scripts/run_strategy_suite.py
```

默认使用 2025-09-01 至本地最新交易日，包含原 Top10 三日调仓基准和 11 套新增策略。新增策略每天收盘检查排名，下一交易日开盘执行买卖；已有仓位只有跌出规定的 Top10/Top20/Top50 才按排名退出。卖出所得现金用于后续符合条件的新标的，未触发退出的仓位不会为了恢复初始比例而每日调仓；没有可买标的时保留现金，下一交易日重新检查。

普通事件策略在持仓最高价首次达到买入价上方 20% 时记录并止盈，两个半仓策略使用 30%。日线回测无法知道分钟内的精确成交顺序，因此使用以下可复现口径：当日最高价触及目标时按目标价卖出；若开盘已经跳空超过目标，则按开盘价卖出。止盈后不会立即买回，必须先跌出该策略的退出排名范围，之后重新满足入场条件才可再次买入。

输出目录为 `backtests/strategy_suite/开始日期_结束日期/`：

- `suite.json`：全部策略的参数、指标和结果目录
- `take_profit_sweep.csv`：保留的原始策略在 10%、15%、20%、25%、30%、40% 和不设止盈下的对照结果

名称带“（两日确认）”的配对版本在第一次跌出卖出排名时不卖；下一信号日回到保留范围便取消待卖，连续第二次仍在范围外才在次日开盘尝试卖出。这样可以直接判断单日排名噪声是否导致过早离场。

两个半仓策略只在标的连续三个交易日进入 Top20 后开仓，每次投入交易前账户权益的 50%，最多同时持有两只，固定 30% 止盈。其中 Top1 版本只检查第一名；Top1/Top2 回退版本在第一名不可买或不满足连续条件时检查第二名。没有候选或可用现金不足半份账户权益时不交易。

事件策略及三日调仓基准均执行以下成交约束：

- 信号只使用当日收盘后可知的数据，交易在下一交易日开盘执行。
- 开盘价达到涨停价时不买入；开盘价达到跌停价时不卖出，卖出意图顺延。
- 普通沪深股票按 10%、创业板/科创板按 20%、北交所按 30% 计算正常涨跌停价。
- 当前配置至少需要 120 日历史，因此不会买入上市初期无涨跌幅限制的新股。
- 排除当前证券简称含 `ST` 的股票；当前名称近似不等同于严格的历史 ST 时点过滤。

交易明细还记录持有期最大盈利和最大不利波动。前者用于观察固定止盈是否截断趋势，后者用于判断排名退出是否过慢。止盈扫描属于同一历史区间上的样本内比较，选出的阈值仍需用未参与选择的新区间做样本外验证，不能直接视为未来最优参数。
- `<strategy_id>/daily.csv`：逐日净值、收益、现金、持仓和交易成本
- `<strategy_id>/trades.csv`：买入/结束日期、持有交易日、价格变化、净收益和退出原因
- `<strategy_id>/threshold_events.csv`：固定止盈事件及对应交易最终卖出日期、价格、收益和原因
- `<strategy_id>/metrics.json`：组合指标、总交易次数、盈利/亏损/持平次数、交易胜率和平均持有期

## 本地 WebUI

先生成一次每日结果和回测结果，然后启动：

```powershell
python scripts/run_webui.py
```

程序会在 `127.0.0.1:8501` 启动仅本机可访问的服务，并自动打开浏览器。每日候选页可以选择任一本地可用交易日；首次计算后会自动缓存。页面包括：

- 带股票代码和当前中文简称的 Top-K 总表、得分概览、单只股票分类得分和底层因子
- 股票选择支持代码、中文简称和拼音首字母模糊搜索，例如 `PAYH` 可匹配平安银行
- 从 2025-09-01 起统计连续进入 Top-20 的天数和累计进入 Top-50 的次数，并显示为可排序字段；连续2次标红、连续3次及以上标紫
- 推荐表支持按排名、连续/累计次数、各类得分、价格和成交额升序或降序排列；代码和简称不参与排序
- 交易信号提醒页合并试验场收益前五与原联合推荐前三，共八套策略；可按日期选择联合候选并查看逐策略买入、止盈、排名退出和辅助价格止损提醒
- 策略总览：统一表格比较累计/年化/超额收益、回撤、事件次数和持有期
- 策略分析：绩效概览、逐日结果、交易区间和盈利事件使用独立二级导航，避免大表同时铺满页面
- 策略试验场：跟踪参数消融进度，展示当前累计收益前二十及对应回撤、胜率和交易次数

## 当前边界

当前已完成量价选股、规则型历史回测、本地账户和 WebUI，并已接入 2000 积分档的低频行情、估值、财务和宏观数据。因子计算优先使用 `daily.pct_chg`（基于除权后的昨收）构造连续价格指数，降低分红送转对动量和趋势的影响，但仍不等于完整前/后复权价格。回测已实现开盘涨停不买、开盘跌停不卖，但尚未模拟盘中开板后的排队成交；历史 ST 也仍是当前简称近似。长期回测结果及联合候选仍应视为研究验证，不构成投资建议。

## 尚缺模块与建议顺序

要从“可运行候选系统”走向“可用于真实研究”，仍建议按以下顺序补齐：

1. **滚动样本外权重校准**：因子诊断已经落地；下一步应只用过去窗口估计权重，在未参与估计的后续窗口验证，避免全样本调参。
2. **更真实的成交模拟**：补齐停牌持仓延续、A 股 100 股整数手、最低佣金、实际调仓价和冲击成本；涨跌停开盘限制已经实现。
3. **历史证券状态**：历史 ST、退市、上市日期和历史名称，解决当前名称映射只代表“现在”的问题。
4. **复权与更多基准**：补齐完整复权价格，并增加中证500等对照；当前主基准已改为沪深300ETF（510300.SH）。
5. **股票池与风险约束**：沪深300/中证500/自定义池、单行业上限、个股权重上限、行业和市值中性化。
6. **基本面与估值因子**：数据已经接入；下一步需构建严格按公告日对齐的质量、成长和估值因子，并先通过诊断再纳入评分。
7. **生产运行**：交易日调度、失败通知、数据完整性告警、日志归档、缓存备份和每日结果对比。

当前多数策略仍显著跑输基准；即使阶段收益为正的策略也有很高回撤和波动。优先级最高的是第 1、2 项，而不是直接用于真实买入。

## DeepSeek AI 分析

AI 模块只复核系统已经算出的当日 Top-20，不替代量价排名，也不会自动下单。它会把以下本地信息整理成结构化输入：8 个量价因子、连续上榜记录、换手率、量比、PE/PB/PS、股息率、市值、按公告日截断的财务三表、低频宏观摘要，以及沪深300ETF最近约20个交易日的表现。历史日期不会读取其后公告的财务数据。

先在项目根目录的 `.env` 中新增一行（不要写入 `config.yaml` 或提交到 Git）：

```dotenv
DEEPSEEK_API_KEY=你的真实DeepSeek密钥
```

启动 WebUI 后选择顶部“AI分析”，选择日期并点击“生成AI分析”。页面加载或浏览器刷新不会自动请求 API；同一日期、同一模型、同一提示词版本且输入数据未变化时直接读取 `data/cache/tushare/ai_analysis.sqlite3`。只有打开“忽略缓存重新生成”才会主动重复调用并产生新的 Token 用量。

也可以使用命令行：

```powershell
python scripts/run_ai_analysis.py
python scripts/run_ai_analysis.py --check
python scripts/run_ai_analysis.py --date 2026-09-10
python scripts/run_ai_analysis.py --date 2026-09-10 --force
```

模型、超时、最大输出 Token 和重试次数在 `config.yaml` 的 `ai` 节点配置；当前默认使用 `deepseek-v4-flash`。结构化复核显式设置 `thinking: disabled`，避免思考过程占满输出额度后没有最终 JSON。正式提示词位于 `jkquant/ai/prompts.py`，强制模型只依据输入数据、标明缺失信息、逐只给出积极因素/风险因素/观察条件/失效条件，并返回可校验的 JSON。当前没有接入新闻、公告正文、研报、舆情或盘中数据，因此 AI 不得声称分析了这些内容。
