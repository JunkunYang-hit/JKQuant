# 亏损交易与打板模块说明（本地行情截至 2026-09-16）

## 结论

- `scripts/audit_worst_trades.py` 审计了最新可交易股票池套件的逐笔策略、连续 Top20 领跑者旧策略和研究策略三个期间，共 19 组结果。列示各组最多 10 笔最差已平仓亏损，共 178 笔；详见 `backtests/loss_audit/worst_10_by_strategy.csv`。这些交易有重复，不能看作 178 个独立样本；最新审计中“回测遗漏除权修正”超过 3 个百分点的为 **0 笔**。
- 先前旧批次确有除权假亏损：**688256.SH 寒武纪**两笔原回测净亏约 34.35%/34.41%，按前收盘除权比值修正后的价差约 -1.86%/-1.95%；Tushare `adj_factor` 实测 2026-05-08 从 1.0000 跳至 1.4912。排除科创板和创业板后，旧价格口径又把 **002245.SZ 蔚蓝锂芯** 的数笔交易夸大约 31～36 个百分点；新版套件用再投资代理修正了此类跳变。
- 在**排除科创板/创业板并加入除权代理**后重跑 2025-09-01 至 2026-09-16，主策略套件 16 套累计收益仍全部为负，最高约 **-21.94%**。因此没有经这批数据验证为正收益的联合买入策略；页面会明确显示暂无，而不会用旧赢家硬凑信号。基线三日调仓仍沿用其独立引擎，尚未统一企业行为事件账本。
- **不能因此推断整体约 -40% 的策略亏损都是假亏损。** 旧套件 14 组交易账本合计 14,142 笔，其中 9,213 笔亏损（约 65.1%；多策略重复交易，不能看作独立抽样）。最差交易中，灵康药业 603669.SH 2026-07-16 至 07-22 原回测约 -35.8%，无显著除权；日线显示 07-17 至 07-21 连续约三个跌停，真实地拉大了亏损。晓程科技 300139.SZ 2026-01-29 至 02-03 约 -32.5%，是在连续急涨后买入，随后出现约 -20% 和 -19% 的连续下跌，亦非除权造成。
- 这些最差交易的旧套件退出原因全部为“跌出 Top10/20/50”，未显示独立的及时止损；买入趋势强股和“下一天仍在 Top20”的命中率，与**从买入到卖出的交易盈利胜率**是不同统计量。高位追入、排名确认滞后、跌停卖不出、手续费与仓位集中可以同时让总收益为负。尤其不能用“下一日晋级胜率”推论交易必定赚钱。
- 新研究引擎已经有 `reinvest_proxy` 除权代理，交易明细中的 `entry_price` 可能已经调整；审计脚本改用 `entry_price_unadjusted` 计算原始价差，再与引擎已调整的价差比较，避免把它重复判作假亏损。该代理仍非真实分红到账、税收和股份登记。

## 当前打板观察口径

新页面 `/limit-up` 使用本地 `daily` 与 `stk_limit` 对比，定义“收盘封板”为收盘价达到当日官方涨停价；按**全市场交易日**连续计数，停牌中断连板。用当前简称与 5% 涨停幅度近似排除 ST。行业来自当前股票列表，并非历史时点行业。该页面无法用日线还原盘中封单、炸板次数、首次封板时刻或实际排队成交。

按账户实际权限，**新推荐与打板页默认排除科创板和创业板**（分别识别 `688/689.SH`、`300/301.SZ` 及股票基础信息板块）。本篇保留旧回测中寒武纪、晓程科技等交易用于说明缺陷；旧批次、试验场与八策略复测未按新股票池重算，不可视作用户可以执行的收益。亏损策略从日常列表隐藏，但历史文件和亏损诊断保留。

首板→二板、二板→三板是“次一交易日仍收盘封板”的事件，不是隔日买入收益。晋级统计和个股模型只使用所选日期以前、结果已知的样本；模型输入包括板前 20 日振幅、复权口径 120 日价格位置、当日放量倍数、换手率、同行业涨停数、一字板和成交额。模型是分阶段的正则逻辑回归；近期 25% 日期留作时间验证，页面会显示总体与每日估计靠前 20% 的晋级率。验证提升不代表绝对概率已经校准，更不保证打板可买入或盈利。人工写的“横盘低位放量”加权分数在验证时效果反而更差，已不用于晋级排序。

截至本地 2026-09-16 缓存、排除科创板和创业板后，历史首板次日封板率约 18.8%，二板次日封板率约 33.8%；留出的较新日期中，首板总体约 15.1%，每日模型前 20% 约 20.6%；二板总体约 26.7%，每日模型前 20% 约 39.3%。页面会随数据更新重新计算。这些是回顾性统计，且当前行业、ST 状态存在历史偏差，建议只作为观察列表。

## 数据与下一步

可复跑：`conda run -n jkquant python scripts/audit_worst_trades.py`。报告生成在 `backtests/loss_audit/`；旧批次历史净值不会追溯改写，也不能直接把单笔修正值加到组合累计收益上。新批次套件已经加入与研究引擎相同的除权再投资代理，但它不是精确的现金分红/送转股份与税收账本。下一步应把官方 `adj_factor` 和分红送转明细进入统一事件账本，并按整数股、现金分红、税费及涨跌停可成交性复测；然后再做不同市场阶段的时间外检验。
